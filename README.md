# C++ Practical Works: от основ к ООП и паттернам проектирования

Коллекция практических и учебных работ по современному программированию на C++.

Проект представляет собой последовательный курс практики: от фундаментального синтаксиса и низкоуровневой работы с памятью до объектно-ориентированного проектирования (ООП), стандартной библиотеки STL и классических паттернов проектирования (GoF).

## 🧪 Инженерный стандарт качества: Тестирование классов эквивалентности (EP)

> [!IMPORTANT]
> **Главное правило для каждой практической работы в репозитории:**
> 1. **Тест-дизайн (EP):** Все ключевые функции, алгоритмы и методы классов должны иметь тестовые сценарии, составленные по методике **разбиения на классы эквивалентности (Equivalence Partitioning, EP)** и дополненные анализом **граничных значений (Boundary Value Analysis, BVA)**.
> 2. **Отдельный пункт меню:** В консольном интерфейсе каждой работы (`main.cpp`) проектируется **специальный пункт меню для автотестов** (например, клавиша `t` / `test`). При его выборе программа автоматически прогоняет все заготовленные сценарии, логирует результаты (`[PASS]` / `[FAIL]`) и выводит сводную статистику.

### 1. Теоретическая база метода (Equivalence Partitioning)

**Суть метода:**
Входное (и выходное) пространство данных разбивается на непересекающиеся подмножества — **классы эквивалентности**. Предполагается, что любой представитель одного класса тестирует логику программы так же эффективно, как и любой другой элемент этого же класса.

#### Стандартная 4-колоночная матрица классов эквивалентности:

| Класс | Тип | Вид | Описание условия |
| :--- | :--- | :--- | :--- |
| `Имя_валидный` | **Валидный** | **Входной / Внутренний / Выходной** | Допустимое значение или штатный диапазон |
| `Имя_невалидный` | **Невалидный** | **Входной / Внутренний / Выходной** | Недопустимое значение (выход за пределы, отказ, ошибка) |

* **Типы:**
  * `Валидный` — нормальное поведение программы, штатный ввод.
  * `Невалидный` — исключительные ситуации, ошибочные аргументы, защитное поведение.
* **Виды:**
  * `Входной` — аргументы функций, пользовательский ввод.
  * `Внутренний` — промежуточные флаги, счетчики, внутреннее состояние объекта.
  * `Выходной` — возвращаемое значение, код ошибки, сгенерированное исключение.

#### ⚖️ Фундаментальные правила составления тестов (Правила изоляции):
1. **Для валидных классов:** разрешено объединять несколько валидных условий в один тест-кейс для минимизации общего числа тестов.
2. **Для невалидных классов (Правило 1-to-1):** один тест проверяет **строго одно невалидное условие**! Запрещено объединять несколько невалидных условий в один сценарий, иначе одна ошибка может замаскировать другую.

#### 🔍 Граничные значения (BVA):
Ошибки чаще всего концентрируются на границах допустимых диапазонов (`<` вместо `<=`, сдвиг на единицу *off-by-one*). Поэтому для каждого диапазона [A, B] проверяются:
* Точка сразу за левой границей: A - 1 (невалидный класс)
* Сама левая граница: A (валидный класс)
* Номинальное значение внутри: (A + B) / 2 (валидный класс)
* Сама правая граница: B (валидный класс)
* Точка сразу за правой границей: B + 1 (невалидный класс)

### 2. Практический пример: Тест-дизайн для функции проверки интервала

Рассмотрим функцию проверки вхождения числа в закрытый диапазон:
```cpp
bool belongsToInterval(int x, int bottom, int top);
```
Пусть фиксированный диапазон проверки: [10, 50] (где bottom = 10, top = 50).

#### Матрица классов эквивалентности:
| Класс | Тип | Вид | Описание |
| :--- | :--- | :--- | :--- |
| `X_внутри_диапазона` | Валидный | Входной | 10 < x < 50 (номинал, например 25) |
| `X_на_левой_границе` | Валидный | Входной | x = 10 (min) |
| `X_на_правой_границе` | Валидный | Входной | x = 50 (max) |
| `X_левее_интервала` | Невалидный | Входной | x < 10 (напр. 9) |
| `X_правее_интервала` | Невалидный | Входной | x > 50 (напр. 51) |
| `Границы_инвертированы` | Невалидный | Входной | bottom > top (некорректная спецификация отрезка) |
| `Результат_True` | Валидный | Выходной | Возвращает `true` |
| `Результат_False` | Валидный | Выходной | Возвращает `false` |

#### Контрольные тест-кейсы (Test Cases):
| TC | Параметры (x, bottom, top) | Покрываемые классы | Ожидаемый результат |
| :---: | :--- | :--- | :---: |
| **TC1** | `x = 25, bottom = 10, top = 50` | `X_внутри_диапазона`, `Результат_True` | `true` |
| **TC2** | `x = 10, bottom = 10, top = 50` | `X_на_левой_границе` (BVA: min) | `true` |
| **TC3** | `x = 50, bottom = 10, top = 50` | `X_на_правой_границе` (BVA: max) | `true` |
| **TC4** | `x = 9, bottom = 10, top = 50` | `X_левее_интервала` (BVA: min - 1) | `false` |
| **TC5** | `x = 51, bottom = 10, top = 50` | `X_правее_интервала` (BVA: max + 1) | `false` |
| **TC6** | `x = 20, bottom = 50, top = 10` | `Границы_инвертированы` (изоляция ошибки) | `false` |

### 3. Архитектурный паттерн: Встроенный Test Runner в C++

Для автономного запуска без внешних тяжелых зависимостей в каждой лабораторной работе используется легковесный мини-раннер:

```cpp
#include <iostream>
#include <string>

// Вспомогательная функция регистрации результата теста
void assertTest(const std::string& testName, bool condition, const std::string& details = "") {
    static int passedCount = 0;
    static int failedCount = 0;

    if (condition) {
        std::cout << "  [PASS] " << testName << std::endl;
        passedCount++;
    } else {
        std::cout << "  [FAIL] " << testName;
        if (!details.empty()) {
            std::cout << " (" << details << ")";
        }
        std::cout << std::endl;
        failedCount++;
    }
}

// Запуск всех тестовых сценариев по методике EP
void runEquivalencePartitioningTests() {
    std::cout << "\n============================================\n";
    std::cout << "  ЗАПУСК ТЕСТОВ (Equivalence Partitioning)\n";
    std::cout << "============================================\n";

    // 1. Тесты belongsToInterval
    assertTest("TC1: Внутри диапазона (x=25, [10, 50])", belongsToInterval(25, 10, 50) == true);
    assertTest("TC2: Левая граница BVA (x=10, [10, 50])", belongsToInterval(10, 10, 50) == true);
    assertTest("TC3: Правая граница BVA (x=50, [10, 50])", belongsToInterval(50, 10, 50) == true);
    assertTest("TC4: Левее диапазона BVA (x=9, [10, 50])", belongsToInterval(9, 10, 50) == false);
    assertTest("TC5: Правее диапазона BVA (x=51, [10, 50])", belongsToInterval(51, 10, 50) == false);

    // 2. Тесты isPrime (пример классов: <2, 2, 3, четные >2, составные нечетные, простые)
    assertTest("TC6: Число < 2 (x=1)", isPrime(1) == false);
    assertTest("TC7: Первое простое (x=2)", isPrime(2) == true);
    assertTest("TC8: Простое нечетное (x=13)", isPrime(13) == true);
    assertTest("TC9: Составное нечетное (x=9)", isPrime(9) == false);
    assertTest("TC10: Отрицательное число (x=-5)", isPrime(-5) == false);

    std::cout << "--------------------------------------------\n";
    std::cout << "  Тестирование завершено.\n";
    std::cout << "============================================\n\n";
}
```

#### Интеграция в консольное меню:
```cpp
cout << "t - Запуск автотестов (EP / BVA)" << endl;
// ...
switch (inputUser) {
    case 't': {
        runEquivalencePartitioningTests();
        break;
    }
    // остальные пункты лабораторной работы
}
```
