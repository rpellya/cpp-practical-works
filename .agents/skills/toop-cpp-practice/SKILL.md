# Регламент выполнения практических работ по ТООП (C++) на 100/100

Данный скилл является единым стандартом качества и чек-листом для всех практических работ (ПР) по дисциплине **«Технологии объектно-ориентированного программирования» (ТООП)**. Руководство составлено на основе реального опыта сдачи, замечаний преподавателя и разбора типичных ошибок, приводящих к снижению баллов.

---

## 1. Фундаментальный принцип: строгость объема изученного материала

> [!CAUTION]
> **Штраф -10% за использование неизученных конструкций языка!**
> Преподаватель оценивает понимание фундаментальных механизмов, а не знание библиотек из современных стандартов.

* **Категорически запрещено использовать на ранних этапах (до изучения в лекциях):**
  1. `auto` — всегда использовать **только конкретные явные типы данных** (`int`, `double`, `char`, `bool`, `Point*` и т.д.).
  2. **Лямбда-выражения** (`[]() { ... }`).
  3. **Обработку исключений (`try / catch / throw`)** — программы должны быть безопасными за счёт защитного программирования, проверок кодов возврата и указателей.
  4. **STL-контейнеры** (`std::vector`, `std::list`, `std::map` и т.д.) — динамические массивы создаются вручную.
  5. **Алгоритмы `<algorithm>`** (`std::sort`, `std::find`) — базовые алгоритмы (сортировка вставками, пузырьком, поиск) реализуются вручную.
  6. **Строковые потоки `<sstream>` (`std::istringstream`, `std::ostringstream`)** — парсинг ввода делается через стандартный `std::cin`.
  7. **Шаблоны (`template`)**, если тема работы не посвящена шаблонам.

## 2. Управление динамической памятью: правила нулевой утечки

> [!IMPORTANT]
> Большинство штрафов (-5% ... -10%) на защитах связаны с некорректной работой с указателями и динамической памятью.

### Правило 2.1. Защита от потери данных при повторном вводе (-5%)
* **Типичная ошибка:** освобождение старого массива до того, как пользователь успешно ввёл новые данные. При ошибке ввода или сбое памяти старые данные теряются.
* **Золотой стандарт:**
  ```cpp
  // 1. Ввод во временный указатель
  int newCount = 0;
  Point* newPoints = inputPointsArray(newCount);

  // 2. Замена только при успешном завершении ввода
  if (newPoints != nullptr && newCount > 0) {
      if (userPoints != nullptr) {
          freePointsArray(userPoints);
      }
      userPoints = newPoints;
      userPointsCount = newCount;
  } else {
      std::cout << "Ввод отменен или произошла ошибка. Предыдущие данные сохранены.\n";
  }
  ```

### Правило 2.2. Выделение памяти без исключений через `new (std::nothrow)`
Так как `try/catch` запрещены, стандартный `new` при нехватке памяти аварийно завершит программу.
* **Стандарт выделения:**
  ```cpp
  #include <new>
  
  Point* arr = new (std::nothrow) Point[size];
  if (arr == nullptr) {
      std::cout << "Ошибка: не удалось выделить память!\n";
      size = 0;
      return nullptr;
  }
  ```

### Правило 2.3. Каскадное освобождение памяти в многомерных массивах (-5%)
При выделении двумерного массива `int** m`: если на строке $i$ произошёл сбой выделения памяти, необходимо в цикле освободить все ранее успешно выделенные строки $0 \dots i-1$, освободить массив указателей и вернуть `nullptr`.

### Правило 2.4. Очистка при прерывании ввода
Если при вводе элементов массива пользователь вводит EOF (`Ctrl+Z` в Windows) или поток сбоит, нельзя возвращать недозаполненный массив:
```cpp
if (std::cin.eof()) {
    delete[] arr;
    size = 0;
    return nullptr;
}
```

### Правило 2.5. Зануление указателей после `delete`
Функция освобождения памяти всегда принимает указатель **по ссылке** и зануляет его:
```cpp
void freePointsArray(Point*& points) {
    if (points != nullptr) {
        delete[] points;
        points = nullptr;
    }
}
```
Повторный вызов `freePointsArray(points)` на `nullptr` должен быть абсолютно безопасен.

### Правило 2.6. Гарантированное освобождение в `main()`
Перед выходом из `main()` (как по пункту меню, так и при разрыве входного потока) все динамические указатели должны быть освобождены.

## 3. Архитектура и стиль C++ кода

### Правило 3.1. Функция `main()` всегда возвращает значение
* Сигнатура: строго `int main()`.
* Все пути завершения обязаны заканчиваться явным `return 0;`.

### Правило 3.2. Никаких дублирующихся глобальных переменных
* **Замечание преподавателя:** *«Лучше избегать повторного объявления одинаковых глобальных переменных (например epsilon) в разных cpp файлах...»*.
* В проекте **вообще не должно быть глобальных переменных**.
* Константы объявляются локально либо выносятся в единый заголовочный файл.
* Все вспомогательные функции, специфичные для одного `.cpp` файла, помечаются спецификатором **`static`** (внутреннее связывание, internal linkage), чтобы исключить конфликты линковки (`LNK2005`).

### Правило 3.3. Чистота пространств имён
* **Категорически запрещено** писать `using namespace std;` в заголовочных файлах (`.h`).
* В `.cpp` файлах рекомендуется явное использование `std::` (`std::cout`, `std::cin`, `std::string`, `std::fabs`).

### Правило 3.4. `const`-корректность
* Все методы классов, не модифицирующие внутреннее состояние объекта, объявляются константными:
  ```cpp
  double getX() const;
  double getArea() const;
  ```
* Сложные типы и объекты передаются по константной ссылке (`const Point&`, `const Square&`), чтобы исключить накладные расходы на копирование.

### Правило 3.5. Защита от погрешностей вычислений с плавающей точкой (`double`)
* Никогда не сравнивать вещественные числа через строгое `==` (`dx1 * dy2 == dy1 * dx2` упадёт на дробных координатах из-за стандарта IEEE 754).
* Всегда использовать сравнение по модулю разности с допуском $0.0001$:
  ```cpp
  if (std::fabs(dx1 * dy2 - dy1 * dx2) < 0.0001)
  ```

## 4. Точность именования и спецификации

> [!WARNING]
> Преподаватель снижает до -10% за отклонение от сигнатур ТЗ (например, `is_prime` вместо `isPrime`).

* **Строго соблюдать сигнатуры:**
  - Названия функций, методов, типов и аргументов переносятся из таблицы варианта символ в символ.
  - Если в задании сказано `getArea` и `getPerimeter` — использовать именно их.
  - Если сказано `Square(Point p1, Point p2, Point p3, Point p4)` — конструктор должен принимать именно такие аргументы и работать при **любом произвольном порядке точек**.

## 5. Стандарт тестирования: Equivalence Partitioning (EP) & BVA

Каждая практическая работа обязана иметь встроенный автономный комплекс тестов, доступный из меню по клавише **`t`**.

### Обязательные компоненты отчёта по каждому тесту:
Требование ТЗ: *«с выводом на консоль ответа от проверяемой функции и правильного ответа»*.
1. Идентификатор и цель тест-кейса (`TCxx: описание`).
2. **Ожидаемый ответ** (`Ожидаемый ответ: ...`).
3. **Полученный ответ функции** (`Полученный ответ: ...`).
4. Вердикт: `[PASS]` или `[FAIL]`.
5. Итоговая сводка: `Всего тестов`, `Пройдено`, `Провалено`.

### Обязательные группы тестов для покрытия 100%:
1. **Штатные валидные сценарии** (номинальные входные данные).
2. **Произвольный порядок данных** (перемешанные координаты/вершины).
3. **Граничные значения (BVA)**:
   - Минимальный размер массива (1 элемент).
   - Минимально допустимый размер для алгоритма (например, 4 точки для поиска 2 линий).
   - Точки на границах диапазонов.
4. **Негативные классы эквивалентности**:
   - Размер меньше допустимого ($< 4$ точек).
   - Передача нулевого указателя (`nullptr`).
   - Вырожденные данные (совпадающие точки, коллинеарные точки, фигуры с нулевой площадью).
5. **Тесты управления памятью**:
   - Проверка, что после вызова очистки указатель равен `nullptr`.
   - Проверка безопасной обработки вызова очистки для `nullptr` (отсутствие падения).

Перед отправкой архива преподавателю обязательно проверьте проект по чек-листу:

- [ ] **Вариант проверен:** номер варианта и формулы соответствуют буквам ФИО.
- [ ] **Сборка MSVC:** проект пересобирается через Rebuild с **0 ошибок и 0 предупреждений**.
- [ ] **Запрещенный синтаксис:** выполнен поиск по проекту — ключевые слова `auto`, `lambda`, `try`, `catch`, `throw`, `sstream` отсутствуют.
- [ ] **Глобальные переменные:** отсутствуют во всех файлах.
- [ ] **Защита памяти:** старые массивы/объекты не затираются до успешного ввода новых.
- [ ] **Функция `main`:** возвращает `int` со значением `return 0;`.
- [ ] **Консольное меню:** все пункты меню работают корректно, буфер потока очищается через `cin.ignore(256, '\n')`.
- [ ] **Автотесты (клавиша `t`):** все тесты проходят со статусом `[PASS]`, в консоль выводятся как полученные, так и ожидаемые ответы.
- [ ] **Формат архива:** строго **`.zip`** (не `.rar`).
- [ ] **Имя архива:** строго по формату `ФамилияИО_НомерВарианта.zip` (например, `ИвановИИ_11.zip`).
- [ ] **Содержимое архива:** только файлы исходного кода (`.h`, `.cpp`) и файлы проекта (`.vcxproj`, `.filters`, `.slnx`), без папок `x64/`, `Debug/`, `.vs/`.
